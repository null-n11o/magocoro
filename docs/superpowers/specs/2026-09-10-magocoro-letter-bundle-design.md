## 1. ゴール

親が写真または短い動画と、ことばと声を**1通にまとめて**送り、祖父母がLINE上で1リンクまたは1本の動画として受け取れる。今回は無料枠に収まる検証用ループだけを形にする。

孫口調の代筆、ハガキ、みてね型の保管、公式アカウントのリマインドは対象外。

成功の見方（事業案の検証指標。本スライスの受け入れとは別）:

- 3家族以上が2週以上、手紙を完成させて送る
- 送った通の過半を祖父母が再生する（自己申告可）
- 親の過半が「バラして送るより楽」と答える

## 2. スコープ / 非スコープ

対象:

- 作る（`/`）→ 端末で圧縮 → 保存 → 手紙（`/letter/:id`）→ URLコピーまたは動画シェア → 別端末で閲覧・再生 → スタンプ
- 媒体は **画像1〜3枚 XOR 動画1本（30秒以内）**。両方は載せない
- 音声は任意、最大30秒（親の吹き込みまたは喃語）
- 本文は親が書く。生成しない。孫口調への誘導文は出さない
- 共有は推測しにくいIDのURL。ログインもパスコードもない
- サーバー上の手紙は作成から90日で閉じる
- 保存用のまとめ動画は**親の端末で作る**。R2には置かない
- 日本語のみ

非スコープ:

- LINE公式アカウント / LIFF / プッシュ / メッセージ自動送信
- Cloudflare Stream、サーバー側エンコード（ffmpeg含む）
- 印刷・郵送・決済・課金
- LLM・テンプレートによる文面生成
- ユーザーアカウント、手紙一覧、削除UI、検索
- 無期限保管、4K原版の保管
- 画像と動画の同時掲載
- 身長・体重、英語、ネイティブアプリ

あとから足すときの継ぎ目: 画面は `LetterApi` にだけ依存する。LINE公式も課金も Worker の奥に足し、画面の窓口は変えない。

## 3. アーキテクチャ

いまの形を保つ。Cloudflare Pages（静的UI）+ Worker（API）+ R2（手紙JSONと圧縮済み素材）。DBなし。アカウントなし。変換はブラウザ。

```text
作る画面
  → 端末で画像/動画/音声を規定サイズへ落とす
  → POST /api/letters（圧縮後のみ）
  → R2（JSON + photos XOR clip + 任意 audio）

手紙画面
  → GET /api/letters/:id
  → GET /api/letters/:id/photos/:n
  → GET /api/letters/:id/clip
  → GET /api/letters/:id/audio
  → POST /api/letters/:id/stamps

まとめ動画
  → 手紙画面で素材を再生しながら MediaRecorder で1本化
  → Web Share（ファイル）または端末保存。R2には上げない
```

- UI: Vite + React + TypeScript + Tailwind。ルートは `/` と `/letter/:id`
- ブラウザは R2 を直接叩かない
- 画面は `LetterApi`（`src/api/letters.ts`）にだけ依存する
- 同一オリジン配信。`/api/*` 以外はSPA
- 秘密値はリポジトリに入れない。外部LLM・決済・LINE SDKにはつながない。例外はフォントCDNのみ
- Workers の CPU は無料枠 10ms を超える処理を置かない。尺の厳密判定は端末側が正。サーバは形式・枚数・XOR・バイト上限だけ見る

IDは `l_` + 32桁hex（16バイト乱数）。ディレクトリ列挙はしない。

### 無料枠に載せる前提（仮定サイズ）

| 素材 | 端末で落とす目標 | サーバ拒否 |
|---|---|---|
| 画像 | 長辺1280px JPEG、1枚 ≦400KB | JPEG/PNG/WebP以外、1枚 1MB超、4枚以上 |
| 動画 | 720p、H.264 または VP8/VP9、30秒以内、≦8MB | 画像と同時、10MB超、非対応形式 |
| 音声 | AAC または Opus、30秒以内、≦0.3MB | 1MB超、非対応形式 |
| 1通のR2合計 | 約10MB以下 | 上記の和が10MBを超えたら 400 |

同時保管の目安は圧縮後10MB × 約1,000通（R2無料10GB）。検証の3〜5家族はこの内側。

## 4. ドメインモデル

`Letter`:

- `id`
- `createdAt`: ISO8601。消印は `YYYY年M月D日`
- `expiresAt`: `createdAt + 90日`。画面には出さなくてよい。API判定用
- `addressTo`: 初期値「じいじ、ばあばへ」。空送信時もこの既定
- `body`: 1〜1000字。改行保持
- `signature`: 1〜20字。既定なし
- `media`: 次のどちらか一方
  - `{ kind: "photos", photos: { contentType }[1..3] }`
  - `{ kind: "clip", clip: { contentType } }`
- `audio`: 無しか `{ contentType }`
- `stamps`: `{ read: number, cute: number }`。初期0

公開JSONはバイトを含まない。写真・クリップ・音声は別URL。

スタンプ:

- `read` … 読んだよ
- `cute` … かわいい！

リンクを知っている人は何度でも押せる。不正利用対策はしない。

90日を過ぎた手紙のJSONは残っていてよい。取得は閉じた扱い（§5）。端末に保存したまとめ動画は対象外。

## 5. API

`POST /api/letters`  
`multipart/form-data`:

- `addressTo`, `body`, `signature`
- `photos`（0〜3）**または** `clip`（0〜1）。両方ある、どちらも無い、は 400
- `audio`（0〜1）

成功: `201` `{ id: string }`。  
失敗: 入力不正は `400`。保存失敗は `503`。

`GET /api/letters/:id`  
期限内: `200`

```json
{
  "id": "l_…",
  "createdAt": "2026-09-10T12:00:00.000Z",
  "expiresAt": "2026-12-09T12:00:00.000Z",
  "addressTo": "じいじ、ばあばへ",
  "body": "…",
  "signature": "はると",
  "media": {
    "kind": "photos",
    "photoUrls": ["/api/letters/l_…/photos/0"]
  },
  "audioUrl": "/api/letters/l_…/audio",
  "stamps": { "read": 0, "cute": 0 }
}
```

動画経路の `media` は `{ "kind": "clip", "clipUrl": "/api/letters/l_…/clip" }`。音声が無ければ `audioUrl` は `null`。

無い・壊れている: `404` `{ "error": "not_found" }`。  
`expiresAt` を過ぎている: `410` `{ "error": "expired" }`。素材URLも同じ。

`GET /api/letters/:id/photos/:n`  
`n` は0始まり。成功は画像バイト。無い番号・無い手紙は `404`。期限切れは `410`。`kind` が `clip` なら `404`。

`GET /api/letters/:id/clip`  
成功は動画バイト。`kind` が `photos`、無い手紙は `404`。期限切れは `410`。

`GET /api/letters/:id/audio`  
成功は音声バイト。音声無し・無い手紙は `404`。期限切れは `410`。

`POST /api/letters/:id/stamps`  
JSON `{ "kind": "read" | "cute" }`。成功 `200` `{ "stamps": { … } }`。無い手紙 `404`。期限切れ `410`。不明な `kind` は `400`。

R2キー:

- `letters/{id}.json`
- `letters/{id}/photo-{n}`
- `letters/{id}/clip`
- `letters/{id}/audio`

## 6. 画面

**作る（`/`）**

- 媒体切替: 「写真」または「動画」。切替したら片方の選択は捨てる
- 写真: 1〜3枚。JPEG / PNG / WebP。選んだ直後に長辺1280の JPEG へ落とす。サーバへは圧縮後の JPEG だけを送る
- 動画: 1本。選んだ直後に720p・30秒以内へ落とす。30秒超は受け付けず「30秒以内にしてください」。サーバは尺を読まない。上限はバイト（10MB）
- 音声: 任意。録音またはファイル。30秒超は受け付けない。無くても作れる
- 宛名、本文、署名。本文近くに孫口調の案内は出さない。プレースホルダは「今週のできごとを、短くでよいので書いてください」
- 「お手紙をつくる」: 媒体が空、本文空、署名空、字数超過では押下不可。理由をその場に出す
- 成功したら `/letter/:id` へ。失敗時は入力を残し「いま保存できません」

**手紙（`/letter/:id`）**

- 便箋。切手枠に写真（複数なら順に）またはクリップ。宛名、本文、署名、消印
- 音声があれば便箋上で再生。自動再生はしない
- 「リンクをコピー」: 手紙URL。成功したら「コピーしました」。注記「このリンクをLINEに貼ると、相手のスマホでも開けます。90日で閉じます」
- 「動画にして送る」: 端末でまとめ動画を作る。できたら Web Share でファイル送信を試す。使えなければ端末に保存し、「LINEのトークに、この動画を送ってください」と出す。失敗してもURLコピーは残す
- スタンプ2種。回数表示。`aria-label`。1回以上押したら `aria-pressed="true"`
- 未知ID: 「お手紙が見つからない」＋ `/` へのリンク。例外画面は出さない
- 期限切れ: 「このお手紙は90日で閉じました」＋ `/` へのリンク。例外画面は出さない

**まとめ動画（端末のみ）**

- 写真経路: 写真を順に出し、音声があれば重ねる。音声が無ければ各写真を均等に、合計6〜15秒
- 動画経路: クリップを1本出し、本文を下部に短く重ねてよい。親の音声があるときはクリップを無音にして親の音声だけ載せる。親の音声が無いときはクリップの音を残す
- 出力は1本。音声が残ること。R2に上げない
- `prefers-reduced-motion` でも作成自体は止めない。便箋の装飾アニメだけ止める

## 7. エラー・境界値

- 写真0かつ動画0 / 本文空 / 署名空 / 字数超過: 作成ボタン押下不可＋理由
- 写真と動画の両方: 作成不可。切替時に片方を捨てるので、APIに届いたら 400
- 非対応形式・サーバ上限超: その素材は受け付けない。他の入力は消さない
- 動画または音声が30秒超（端末判定）: 受け付けない
- 保存・通信失敗: 「いま保存できません」。入力は残す
- まとめ動画の作成失敗: 「動画にできませんでした。リンクを送ってください」。URLコピーは使える
- 未知ID: 見つからない表示。期限切れ: 閉じた表示。例外画面なし
- 期限切れへのスタンプ: 足さない（`410`）

削除UIは作らない。

## 8. デザイン制約

現行の便箋制約を維持する。

- 和紙・便箋。地 `#f7f2e9`、面 `#fffdf8`、本文 `#33302a`、補助 `#8a7f72`、罫線 `#ddd2c2`、強調（朱） `#c4543a`
- 切手風フレームは白縁＋波線。日付は消印風に小さく
- 紫・ネオン・金グラデ・飾り絵文字は禁止。本文中の絵文字は親が書いた場合のみ素通し
- 見出しと本文は Noto Sans JP。`lang="ja"`
- 動き150–400ms。`prefers-reduced-motion` で装飾は無効化
- タップ面44px以上。スタンプは `aria-label`＋`aria-pressed`
- ページ全体の横スクロール禁止。最大幅モバイルカラム（`max-w-lg`）中央寄せ

## 9. 要件追跡

| ID | 要件 | 根拠 | 優先 | 受け入れ |
|---|---|---|---|---|
| REQ-01 | 1通に写真または短い動画、ことば、任意の声を載せる | H-06 | 必須 | 作る画面から1通ができ、手紙画面で媒体・本文・声が揃って再生できる |
| REQ-02 | 画像最大3枚 XOR 動画30秒。同時掲載しない | 容量採用 | 必須 | 両方選んで送れない。APIも 400 |
| REQ-03 | 音声は任意・最大30秒 | 0〜1歳 | 必須 | 無しでも作れる。30秒超は作れない |
| REQ-04 | 上げる前に端末で圧縮する。原版は置かない | 無料枠 | 必須 | サーバに届く画像は1枚1MB以下、動画は10MB以下 |
| REQ-05 | Streamもサーバ変換も使わない | Workers 10ms | 必須 | 依存に Stream / ffmpeg サーバが無い |
| REQ-06 | 保存用の1本は端末で作る。R2に置かない | 音声を残す／容量 | 必須 | まとめ動画作成後も R2 に clip 以外の結合ファイルが増えない |
| REQ-07 | 祖父母はURLまたはトークの動画で見る | LINE前提 | 必須 | 別ブラウザでURLが開く。動画シェアは対応ブラウザでファイルが渡せるか、失敗時にURLへ落ちる |
| REQ-08 | 本文は親の入力のまま。代筆しない | H-04棄却 | 必須 | 生成APIも孫口調の案内もない |
| REQ-09 | 作成から90日でWeb手紙を閉じる | 無料枠 | 必須 | `expiresAt` 超過は 410 と閉じた表示 |
| REQ-10 | 公式プッシュ・LIFF・課金・ハガキを足さない | 検証範囲 | 必須 | それらのSDK・画面が無い |
| REQ-11 | スタンプ2種が残る | 現行ループ | 必須 | 再読込後も回数が残る |
| REQ-12 | 未知・期限切れは例外画面にしない | 現行制約 | 必須 | 専用文言と作る導線 |

## 10. テストと受け入れ

自動テスト:

- Worker: 写真経路で作れる、動画経路で作れる、両方は 400、音声なしで作れる、取得できる、期限切れは 410、スタンプが増える、無いIDは 404
- 圧縮: 大きなJPEGを選ぶと、アップロード前のファイルが1MB以下になる
- 作る画面: 媒体空・本文空でボタン不可、写真/動画切替で片方が消える、成功で手紙へ
- 手紙画面: 媒体・本文・署名が出る、音声ありなら再生できる、未知IDと期限切れは専用表示
- まとめ動画: 写真＋音声から Blob が1本できる（jsdomで MediaRecorder が使えなければ、合成関数にダミーフレームを渡す単体テスト）

受け入れ（人が確認）:

- 写真3枚＋短い文＋声で便箋が作れる
- 30秒以内の動画＋短い文でも作れる。写真と同時には作れない
- 別ブラウザで同じURLが開き、中身が一致する
- まとめ動画を再生すると声が聞こえる
- リンクをLINEに手動で貼って開ける
- 90日後相当（`expiresAt` を過去にしたデータ）は閉じた表示になる
- 必須欠けでは作れない
- 全テストPASS、本番ビルドが通る

デプロイ・公開URL確定は明示依頼があるまで対象外。
