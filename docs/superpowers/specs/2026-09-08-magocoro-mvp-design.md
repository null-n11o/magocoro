## 1. ゴール

親が写真2〜3枚＋箇条書きメモを入れるだけで、孫一人称の「Web手紙」プレビューがその場で作れ、祖父母向け共有リンクとワンタップ反応（スタンプ）まで回るMVP。外部コストゼロ（APIキー・従量課金・外部契約なし）で、検証指標のうち「4週継続率」と「祖父母リアクション率」を測れる状態にする。有料転換の測定はスコープ外（Phase3）。

## 2. スコープ / 非スコープ

- 対象: Web手紙の作成→プレビュー→共有→スタンプ反応の1ループ。日本語のみ。
- 入力: 写真（1〜3枚、端末内ファイル）、メモ（箇条書きテキスト）、身長・体重（任意）、宛名（じいじ・ばあば等の呼称、既定値あり）。
- 出力: 便箋プレビュー（切手風写真＋孫口調の本文＋消印風パーツ）、共有リンク（同一ブラウザ内で開けるID付きURL）、スタンプ反応（「読んだよ」「かわいい！」の2種＋カウント）。
- 文面生成はテンプレート式（外部LLMなし）。`LetterGenerator` インターフェースの背後に隠し、将来LLM実装へ差し替え可能にする。
- 保存はlocalStorageのみ（手紙データ＋スタンプ）。サーバ・DB・外部通信なし。
- 非スコープ: LINE LIFF連携、印刷・郵送API、Stripe決済、ユーザー認証、画像の外部アップロード、英語対応、ネイティブアプリ。

## 3. アーキテクチャ

静的SPA（Vite + React + TypeScript + Tailwind、Vitest）。サーバDBなし。

```text
入力フォーム（src/compose/）→ LetterInput → LetterGenerator（src/letter/generator.ts）
→ Letter → プレビュー（src/preview/）／保存はLetterStore抽象（src/store/storage.ts）
→ 共有リンク（/letter/:id）→ スタンプ反応（src/reaction/）
```

- 画面は `LetterStore` 抽象（`saveLetter()` / `getLetter(id)` / `addStamp(id, kind)`）にだけ依存する。将来Workers+R2へ差し替えても画面は変更しない。
- 文面生成は `LetterGenerator` 抽象（`generate(input): Letter`）にだけ依存する。MVP実装はテンプレート式（`TemplateLetterGenerator`）。LLM実装は将来の差し替え先で、MVPでは作らない。
- 写真は端末内でDataURL化しlocalStorageに保存する（1通あたり合計2MB上限、超過時は保存前にエラーを出す）。

## 4. ドメインモデル

- `LetterInput`: photos（DataURL配列1〜3件）、memos（文字列配列1〜5件、各140字以内）、heightCm・weightKg（任意・数値）、addressTo（宛名、既定「じいじ、ばあばへ」）、childName（任意、既定「ぼく」/「わたし」選択）。
- `Letter`: id（`l_`＋英数12桁）、createdAt（ISO8601）、input の写し、body（孫口調の本文）、photoFrames（切手風表示用の順序情報）。
- テンプレート生成規則: 冒頭は `{addressTo}。`、本文はメモ1件ごとに1文へ変換する（語尾は「〜だよ」「〜したよ」「〜たべたよ」の3種を文脈で選択、詳細は実装計画Task 2のテストが正本）。身長・体重の入力がある場合のみ末尾に「いま {height}cm {weight}kg だよ」を付ける。写真が0枚のときは生成せずエラーを返す（写真必須）。
- `StampKind`: `read`（読んだよ）・`cute`（かわいい！）の2種。各Letterに種別ごとのカウントを持つ。

## 5. 画面

- 作る（`/`）: 写真選択（1〜3枚、プレビュー付き）・メモ入力（箇条書き3行まで）・身長体重（任意）・宛名・一人称の入力。「お手紙をつくる」ボタンで生成→プレビューへ遷移。未入力（写真0枚・メモ0件）はボタンを押下不可にする。
- プレビュー（`/letter/:id`）: 便箋レイアウト。本文・切手風写真・消印風パーツ（作成日＋身長体重がある場合のみ印字）。「リンクをコピー」ボタン。スタンプボタン2種＋カウント表示。未知IDは「お手紙が見つからない」＋作る画面への導線。
- 共有リンクは同一ブラウザでのみ開ける（localStorage由来の制約）。リンク先にその旨を1行で注記する。

## 6. エラー・境界値

- 写真0枚・メモ0件: 生成不可（ボタン押下不可＋理由表示）。
- 写真合計2MB超過: 保存前に「写真が大きすぎます」と表示し、生成結果を破棄しない（入力は保持）。
- localStorage容量超過（QuotaExceededError）: 「ブラウザの容量がいっぱいです」と表示する。
- 未知ID・破損データ: 専用表示＋作る導線にする。例外画面を出さない。

## 7. デザイン制約（全文は AGENTS.md）

- 和紙・便箋の質感。地 `#f7f2e9`、面 `#fffdf8`、本文 `#33302a`、補助 `#8a7f72`、罫線 `#ddd2c2`、強調（朱） `#c4543a`。切手風フレームは白縁＋波線表現。
- 紫・ネオン・金グラデ・絵文字の装飾利用は禁止。本文中の絵文字はユーザーがメモに入れた場合のみ素通しする。
- 見出しと本文は Noto Sans JP。動き150–400ms（`prefers-reduced-motion` で無効化）。タップ面44px以上。スタンプボタンは `aria-label`＋`aria-pressed`。文書言語 `lang="ja"`。
- ページ全体の横スクロール禁止。最大幅モバイルカラム（`max-w-lg`）中央寄せ。
- 秘密値・外部キーは持たない。外部通信は発生させない（フォントCDNを除く）。

## 8. 受け入れ条件

- 写真＋メモからプレビューが生成され、切手風写真・孫口調本文・消印風日付が表示される。
- 身長・体重の入力がある場合のみ印字され、未入力では出ない。
- 共有リンクを同一ブラウザで開けて内容が一致する。未知IDでは専用表示になる。
- スタンプ2種の押下・カウント・再訪残存が動く。
- 写真0枚・メモ0件では生成できない。2MB超過・容量超過の表示が出る。
- 全テストPASS＋`npm run build` 成功で `dist/` が静的配信可能な状態。
