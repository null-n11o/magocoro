- 置き換え: `docs/superpowers/specs/2026-09-08-magocoro-mvp-design.md`（localStorage・文面生成の下書き。本ファイルが正本）

## 1. ゴール

親が写真と孫口調の本文を入れて便箋を作り、リンクをLINEに貼ると祖父母のスマホで同じ手紙が開き、ワンタップのスタンプで返事できる。今回はWeb手紙の1ループだけを形にする。LINE公式連携・文面の自動生成・ハガキ郵送は対象外。

## 2. スコープ / 非スコープ

対象:

- 作る（`/`）→ 保存 → 手紙（`/letter/:id`）→ リンクコピー → 別端末で閲覧 → スタンプ、の1ループ
- 日本語のみ
- 入力: 写真1〜3枚、宛名、本文、署名（子どもの呼び名）
- 本文は親が書く。画面に「孫の口調で書いてください」と案内する。生成（テンプレート / LLM）はしない
- 共有は推測しにくいIDのURL。ログインもパスコードもない。リンクを知っている人だけが読める
- 親はリンクをコピーして、いつものLINEトークに自分で貼る

非スコープ:

- LINE公式アカウント / LIFF / メッセージ自動送信（次スライス）
- 印刷・郵送API、決済（その次）
- LLM・テンプレートによる文面生成
- ユーザーアカウント、手紙一覧、削除UI、検索
- 身長・体重、英語、ネイティブアプリ

あとから足すときの継ぎ目: 画面は保存APIクライアントにだけ依存する。LINEもハガキも Worker の奥に足し、画面の窓口は変えない。

## 3. アーキテクチャ

Cloudflare Pages（静的UI）+ Worker（API）+ R2（手紙JSONと写真）。DBなし。アカウントなし。

```text
作る画面 → POST /api/letters → R2（JSON + 写真）
手紙画面 → GET /api/letters/:id
         → GET /api/letters/:id/photos/:n
         → POST /api/letters/:id/stamps
```

- UI: Vite + React + TypeScript + Tailwind。ルートは `/` と `/letter/:id`
- ブラウザは R2 を直接叩かない。Worker の上記4本だけを使う
- 画面は `LetterApi`（`src/api/letters.ts`）にだけ依存する。fetchの中身を変えても画面は変えない
- 写真は Worker 経由で返す。R2バケットは公開にしない
- 手紙一覧APIは作らない。IDを知らないと読めない
- 同一オリジンで配信する（PagesのSPAとWorkerを一体）。`/api/*` 以外のパスはSPAにフォールバックし、`/letter/:id` をReact Routerが受ける
- 秘密値はリポジトリに入れない。アプリから外部LLM・決済・LINEにはつながない。例外はフォントCDNのみ

IDは `l_` + 32桁hex（16バイト乱数、`crypto.getRandomValues`）。推測困難を要件とする。ディレクトリ列挙はしない。

## 4. ドメインモデル

`Letter`:

- `id`: 上記形式
- `createdAt`: ISO8601。画面の消印は `YYYY年M月D日`
- `addressTo`: 宛名。入力の初期値は「じいじ、ばあばへ」。空で送った場合もこの既定を使う
- `body`: 親が書いた本文。1〜1000字。改行は保持する
- `signature`: 署名（子どもの呼び名）。1〜20字。既定値は置かない（子どもごとに違うため）
- `photos`: 1〜3枚。JPEG / PNG / WebP。1枚あたり2MBまで。並びはアップロード順
- `stamps`: `{ read: number, cute: number }`。初期値はどちらも0

文面生成結果は持たない。本文は入力がそのまま載る。

スタンプ種別:

- `read` … 読んだよ
- `cute` … かわいい！

リンクを知っている人は何度でも押せる。押すたびにサーバ側の該当カウントが1増える。不正利用対策は今回しない。

## 5. API

`POST /api/letters`  
`multipart/form-data`: `photos`（1〜3ファイル）、`addressTo`、`body`、`signature`。  
成功: `201` `{ id: string }`。  
失敗: 写真0枚・形式不正・1枚2MB超・本文空または1000字超・署名空または20字超は `400`。保存失敗は `503`。

`GET /api/letters/:id`  
成功: `200`

```json
{
  "id": "l_…",
  "createdAt": "2026-09-08T12:00:00.000Z",
  "addressTo": "じいじ、ばあばへ",
  "body": "…",
  "signature": "はると",
  "photoUrls": ["/api/letters/l_…/photos/0"],
  "stamps": { "read": 0, "cute": 0 }
}
```

無い・壊れている: `404` `{ "error": "not_found" }`。

`GET /api/letters/:id/photos/:n`  
`n` は 0始まり。成功は画像バイトと正しい `Content-Type`。無い番号・無い手紙は `404`。

`POST /api/letters/:id/stamps`  
JSON `{ "kind": "read" | "cute" }`。成功: `200` `{ "stamps": { "read": 1, "cute": 0 } }`。無い手紙は `404`。不明な `kind` は `400`。

R2キー:

- `letters/{id}.json`
- `letters/{id}/photo-{n}`（`n` は 0始まり）

## 6. 画面

**作る（`/`）**

- 写真1〜3枚（プレビュー付き。JPEG / PNG / WebP）
- 宛名（初期値「じいじ、ばあばへ」）
- 本文（1〜1000字）。近くに「孫の口調で書いてください」と案内。プレースホルダ例: 「じいじ、ばあば、げんき？ きょうね、…」
- 署名（1〜20字。プレースホルダ例: 「はると」）
- 「お手紙をつくる」: 写真が1枚もない、本文が空、署名が空のときは押下不可。理由をその場に出す。本文1000字超・署名20字超も押下不可
- 成功したら `/letter/:id` へ遷移。失敗時は入力を残し、「いま保存できません」を出す

**手紙（`/letter/:id`）**

- 便箋。切手風写真、宛名、本文（改行維持）、署名、消印風の日付
- 「リンクをコピー」: 現在の手紙URLをクリップボードへ。成功したら「コピーしました」
- 注記1行: 「このリンクをLINEに貼ると、相手のスマホでも開けます」
- スタンプ2種。ラベルは「読んだよ」「かわいい！」。回数を表示。`aria-label` を付ける。この表示中に1回以上押したら `aria-pressed="true"`
- 未知ID・破損: 「お手紙が見つからない」と、作る画面（`/`）へのリンク。例外画面は出さない

## 7. エラー・境界値

- 写真0枚 / 本文空 / 署名空 / 本文1000字超 / 署名20字超: 作成ボタン押下不可＋理由表示
- 写真が JPEG / PNG / WebP 以外、または1枚2MB超: その写真は受け付けない。他の入力は消さない
- 保存・通信失敗: 「いま保存できません」。入力は残す
- 未知ID・破損データ・無い写真: 専用表示＋作る導線。例外画面を出さない
- 無い手紙へのスタンプ: 足さない（`404`）。画面は見つからない表示

削除UIは作らない。オブジェクトはIDを知る人だけが読める。

## 8. デザイン制約

- 和紙・便箋の質感。地 `#f7f2e9`、面 `#fffdf8`、本文 `#33302a`、補助 `#8a7f72`、罫線 `#ddd2c2`、強調（朱） `#c4543a`
- 切手風フレームは白縁＋波線。日付は消印風に小さく
- 紫・ネオン・金グラデ・飾り絵文字は禁止。本文中の絵文字は親が書いた場合のみ素通し
- 見出しと本文は Noto Sans JP。文書言語 `lang="ja"`
- 動き150–400ms。`prefers-reduced-motion` で無効化
- タップ面44px以上。スタンプは `aria-label`＋`aria-pressed`
- ページ全体の横スクロール禁止。最大幅モバイルカラム（`max-w-lg`）中央寄せ

## 9. テストと受け入れ

自動テスト:

- Worker: 作成できる、取得できる、スタンプが増える、無いIDは `404`
- 作る画面: 必須欠けでボタンが押せない、成功で手紙ページへ進む
- 手紙画面: 宛名・本文・署名・写真が出る、スタンプで数が増える、未知IDは専用表示

受け入れ:

- 写真＋宛名＋本文＋署名から便箋が作れる
- 別のブラウザ（別端末相当）で同じURLを開くと、写真を含む内容が一致する
- リンクコピーの文言どおり、LINEに手動で貼って開ける前提のURLになっている
- スタンプ2種がカウントされ、再読み込み後も残る
- 必須欠けでは作れない。2MB超・非対応形式の表示が出る
- 未知IDは例外画面に落ちない
- 全テストPASS、本番ビルドが通り、Pages+Workerとして静的UIとAPIを同一オリジンで出せる
